# Hindi/English (i18n) system

dusrel.com **do bhashaon** mein hai — har page ke do URLs:

| English | Hindi |
|---|---|
| `/apps/shrinkit` | `/hi/apps/shrinkit` |
| `/apps/shrinkit/download/chrome` | `/hi/apps/shrinkit/download/chrome` |

## Strings kahan hain

`src/i18n/en.ts` aur `src/i18n/hi.ts` — dono mein **same structure, same keys**. TypeScript `en.ts` se type derive karta hai, isliye agar `hi.ts` mein koi key chhoot gayi toh `npx tsc --noEmit` turant error dega.

```ts
// en.ts
export const dict = {
  nav: { home: 'Home', apps: 'Apps' },
  appContent: {
    'shrinkit': { name: 'ShrinkIt', tagline: '...', ... },
  },
  appPages: {
    'shrinkit': { metaTitle: '...', metaDesc: '...', ... },
  },
};
```

## Nayi string add karna

1. Pehle `en.ts` mein add karo
2. Phir `hi.ts` mein **same key** par Hindi translation dalo
3. `npx tsc --noEmit` chalao — missing key pakdi jayegi

## Apvaad (exceptions)

- **Download pages** (`src/data/downloads.ts`) — inke strings i18n files mein **nahi** hote. Har string `{ en, hi }` object mein usi file mein likhi hoti hai. Janboojhkar aisa hai taaki ek app ka saara download content ek jagah rahe.
- **Web apps** (shrinkit, ricsline waghera) — unka apna alag i18n system hai (20 locales tak). Yeh chapter sirf dusrel.com site ke liye hai.

## hreflang aur SEO

Har page par dono languages ke alternate links auto-generate hote hain — Google ko pata chalta hai ki `/hi/...` Hindi version hai. Iske liye kuch manual karne ki zaroorat nahi; `Base.astro` layout sambhalta hai.
